## Описание

Это демо-бот, который демонстрирует возможности Bot API через интерактивные сценарии. Каждый из них — это пошаговый обзор отдельной функциональности: работа с сообщениями, клавиатурой, вложениями, администрирование чата и т.д.

## Установка бота

1. Скачайте репозиторий:

git clone git@github.com:max-messenger/demo-bot-go

2. Соберите проект:

```bash
make dev_env_up                              
go run ./cmd/demo_bot -c config/demo_bot/config.local.yaml
```

Конфигурационный файл `config/demo_bot/config.local.yaml` содержит локальные параметры среды для запуска и работы `demo_bot`:
- Токен бота
- Подписку на обновления — `/webhook/public-bot`
- Приложение на localhost: `:8008`
- Системный порт — `:23570`
- Redis на localhost: `:6379`

## Локальное тестирование

1. Для проведения тестов без связи с реальным бэкендом мессенджера MAX запустите локальную заглушку на порту `:19090` (эндпоинты: `/me`, `/subscriptions`):

```go
go run ./cmd/stub 
```

2. Сгенерируйте код:

```go
make generate
```

Команда запустит все `go:generate`-директивы: моки через `mockgen` и swagger-документацию через `swag init`

3. Выполните автоматическую проверку кода проекта:

```go
make lint
```

Команда запустит `golangci-lint run --fix` — это 48 линтеров. Проверяется сложность, длина строк, порядок импортов и т.д. Выявленные ошибки исправляются автоматически, если есть возможность

4. Выполните unit-тестирование:

```go
make test_unit
```

Через `gotestsum` запустятся тесты с префиксом `TestUnit*`:
- С покрытием `-cover`
- C детектором гонок и сброшенным кэшем — `-race`

Профиль покрытия описан в `coverage/unit.txt`. Внешние зависимости отсутствуют — только моки

5. Выполните оценку процента покрытия кода unit-тестами (запускать строго после шага 3):

```go   
make test_cover
```

Произойдет фильтрация `coverage/unit.txt` через `.covignore` и вывод общего процента покрытия

## Возможности демо-бота

После сборки и тестирования демо-бота введите команду `/<name>` в консоли или перейдите по ссылке https://max.ru/max_demo_bot и нажмите **Начать**

Бот предложит список демонстрационных сценариев:

- Личные чаты:
    - `/message` — отправка, редактирование, ответ, удаление сообщений
    - `/actions` — индикаторы действий:
        - `«печатает…»`
        - `«отправляет фото…»`
        - `«записывает аудио…»`
        - `«отправляет файл…»`
    - `/keyboard` — все виды клавиатур и кнопок:
        - `callback` — автоматический ответ на запрос
        - `link` — кнопка со ссылкой
        - `reply_keyboard` — запросы геолокации, контакта, отправка сообщения в чат
        - `clipboard` — копирование указанного текста
    - `/attachments` — картинка, стикер, контакт, локация, шеринг контента
    - `/upload` — загрузка и отправка файла
    - `/botinfo` — получение и изменение информации о боте

- Групповые чаты:
    - `/chat` — закрепление/открепление сообщения в чате, смена названия чата
    - `/members` — добавление и исключение участников
    - `/admins` — назначение, просмотр, снятие администраторов
    - `/leave` — выход бота из чата
    - `/mention` — отправка упоминаний и беззвучных сообщений

Для групповых сценариев бот предварительно проверяет, есть ли у него нужные права администратора, и предупреждает, если их не хватает

## Архитектура

Бот разработан на базе Go-микросервиса на фреймворке [`uber-go/fx`](https://pkg.go.dev/go.uber.org/fx)

#### Процесс начальной загрузки, конфигурации и запуска приложения

- Система последовательно передаёт управление по цепочке файлов: `cmd/demo_bot/main.go` → `internal/app/app.go:CreateApp` → `box.go:Box.CreateApp`
- Фреймворк [`uber-go/fx`](https://pkg.go.dev/go.uber.org/fx) собирает fx-модули в единое приложение — `fx.App`
- Конфигурационный файл передаётся флагом `-c` (по умолчанию `config.yaml`)

#### Архитектурные слои в `internal/app/`

- `domain/` — бизнес-сущности
- `services/` — бизнес-логика
- `router/` — HTTP-роутер на `chi`

#### Подключение и регистрация модулей

- В файле инициализации `internal/app/fx.go` подключаются все ключевые модули системы: `rediscli`, `locker`, `maxbot`,
  `repository`, `services`, `router`, `docs`

- Контроллеры регистрируются через `group:"controller"`

- Сервисы жизненного цикла регистрируются через `group:"grace"`

#### Ядро

Внутри слоя бизнес-логики `internal/app/services/bot/scenario/` находится ядро бота — система сценариев

Сценарий реализует интерфейс `Scenario` со следующими параметрами:
- `Name` — уникальное имя сценария
- `Description` — описание сценария
- `ChatType` — тип чата, в котором работает сценарий
- `RequiredPermissions` — права доступа
- `Handle` — функция обработки входящих сообщений и запуска логики

Для общения с пользователем бот использует `ScenarioState`, который содержит: имя сценария, шаг, произвольные данные.  `ScenarioState` хранится в `Redis` и привязан к пользователю

По правилу фильтрации обычные текстовые сообщения игнорируются, пока нет активного сценария, а обработка идёт только по командам и кнопкам (например, `/start`)

Для предотвращения параллельной обработки одного чата используется распределённая блокировка в `Redis` на 10 секунд (`TTL 10s`)

Папка `pkg/` — это общая инфраструктура (подключения, мониторинг, промежуточное ПО, распределённая блокировка). Этот код не модифицируется. Если требуются доработки, обратитесь к мейнтейнеру общего фреймворка
